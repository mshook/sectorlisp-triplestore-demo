● Clean. Here's what was added and how it works:

  TRIPLES-TO-ENTITIES — three helpers compose it:
  1. UNIQUE-SUBJECTS — scans the DB recursively to end, then prepends each
  subject only if not already seen (using MEMBER-EQUAL). Works correctly with
  list subjects like (COMPUTER WIZARD) because it uses EQUAL, not EQ.
  2. PO-PAIRS-FOR SUBJ DB — makes a second pass collecting every (P O) pair
  where the subject matches, producing a list like ((JOB (COMPUTER WIZARD)) 
  (SALARY 60000) ...).
  3. BUILD-ENTITY-LIST — maps over the subject list, calling PO-PAIRS-FOR for
  each and wrapping the result as (ENTITY S (P1 O1) (P2 O2) ...).

  ENTITIES-TO-TRIPLES — one helper:
  - EXPAND-PO SUBJ PO-PAIRS — walks the (P O) pair list, building each triple as
   (CONS (QUOTE TRIPLE) (CONS SUBJ (CAR PO-PAIRS))). The key insight is that
  (CONS SUBJ (P O)) naturally produces (SUBJ P O), so prepending TRIPLE gives
  the correct 4-element list.
  - ENTITIES-TO-TRIPLES iterates entities, expands each with EXPAND-PO, and
  APPENDs the results.

  One behavioural note: subjects in the output of TRIPLES-TO-ENTITIES appear in
  reverse order of first appearance (a consequence of the tail-recursive
  deduplication strategy). The triple content within each entity preserves
  original DB order.
